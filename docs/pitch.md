# ピッチ資料の内容

5分のピッチ用スライド（全10枚）の内容です。スライドと同じ順番で、見出しの内容と話す内容（秒数の目安つき）をまとめています。

スライドは「マニュあっぷ ピッチ資料」（Slides）にあります。仕様と食い違う箇所があれば、仕様書（[spec.md](spec.md)）と要件定義（[requirements.md](requirements.md)）を優先して、この資料を直します。

## 1. 表紙

- 題名：マニュあっぷ
- 説明：マニュアルと「誰がどこまでできるか」をつなげて見える化する、人事部のアプリ
- NCT × RUNTEQ JOINT HACKATHON、Aチーム、発表はまなぴ
- 話す内容（約15秒）：Aチームのまなぴです。人事部の「誰がどこまでできるか」が分からない、という困りごとを解決するアプリ、マニュあっぷを紹介します。

## 2. 課題

- 見出し：人事部では、「誰がどこまでできるか」が見えない
- 給与計算：できるのは1人だけ。ベテランの山本さんが休むと止まるが、部長は気づいていない
- 年末調整：誰が読み直したか不明。10/15にマニュアルを改定したが、全員に伝わったか分からない
- 異動・引き継ぎ：口頭で一から教える。異動のたびに、手順を話して教え直している
- まとめの一文：人事の作業は本業ではないので後回しになり、手順書もバラバラのまま。教え直しのたびに、本人に聞いて回る手間がかかる
- 注意：この3つは、想定する場面です。実測の数字ではありません
- 話す内容（約40秒）：人事部では、よくある3つの場面があります。給与計算はできる人が1人だけで、休むと止まるのに部長が気づかない。年末調整はマニュアルを改定しても、誰が読み直したか分からない。異動のたびに、手順を口頭で一から教え直している。人事の作業は本業ではないので後回しになりがちで、仕組みが整わないまま残っています。

## 3. 解決策

- 見出し：マニュアルとスキルを、1つにつなぐ
- マニュアル：作業ごとに手順をまとめる。改定すると版が上がり、履歴に残る
- スキルレベル：誰がどの作業をどこまでできるかを、一覧で見える化する
- 研修：期限をつけて、誰が誰に教えるかを頼める。教えた記録も残る
- まとめの一文：部長は「できる人が少ない作業」を見つけて、そのまま研修を頼める
- 話す内容（約30秒）：マニュあっぷは、3つをつなげたアプリです。1つ目はマニュアル。2つ目は、誰がどこまでできるかを見せるスキルレベル。3つ目は、教える人と期限を決めて頼める研修です。部長は、できる人が少ない作業を見つけて、そのまま研修を頼めます。使う人は管理者の部長とスタッフで、右上のスイッチで切り替えます。

## 4. スキルレベル

- 見出し：0〜4の5段階。部長の判断は「見立て」で添える
- レベル0：未着手
- レベル1：マニュアル確認済み
- レベル2：研修済み（教えた人が「教え終わった」を押す）
- レベル3：先輩のもとでできる（自己申告）
- レベル4：最後まで1人でできる（自己申告）
- 管理者の見立て：▲ 研修権限（教えられる）、▼ 要研修、▽ 研修済み（▼から）、◇ 教えるのは後回し
- 注意：見立てはスタッフの画面には出ません
- 話す内容（約35秒）：スキルレベルは、作業ごとに0から4の5段階です。1はマニュアルを確認した、2は研修を受けた、3と4は本人が自己申告します。部長の判断は、レベルとは別の「見立て」で添えます。たとえばレベル3でも教えられる人には▲、研修が必要な人には▼です。見立てはスタッフには見せません。同僚どうしの比べ合いや、「教えなきゃいけない」という負担を避けるためです。

## 5. 画面イメージ（スキルマップ）

- 見出し：「できる人が1人」の作業が、すぐ見つかる
- 作業と人の一覧で、数字がレベル。できる人が1人の作業は色が変わり、「できる人1人」と出る
- 警告で気づく：できる人が1人以下の作業は、色と「できる人○人」で分かる
- そのまま研修へ：研修画面で、教える人と期限を決めて頼める
- 注意：画面の数字は、サンプルデータのイメージです。本番のモックに差し替える場合は、スライドを直します
- 話す内容（約30秒）：これがスキルマップのイメージです。作業と人の一覧で、数字がレベルです。できる人が1人の作業は色が変わり、警告が出るので、給与計算のような「1人しかできない作業」にすぐ気づけます。そのまま研修の画面に進んで、教える人と期限を決められます。

## 6. 使い方の流れ

- 見出し：見つける → 頼む → 教える → 自己申告

1. 見つける（部長）：スキルマップで、できる人が少ない作業を見つける
2. 頼む（部長）：日付・教える人・教わる人を選んで、研修を保存する
3. 教える（教える人）：「教え終わった」を押すと、教わった人がレベル2になる。記録（誰から・いつ）が残る
4. 自己申告（教わった人）：できるようになったら、レベル3・4を自分で申告する

- まとめの一文：部長の承認は不要。本人の申告と判断が違うときだけ、見立て（▲▼◇）で添える
- 話す内容（約40秒）：部長がスキルマップで、できる人が少ない作業を見つけます。研修の画面で、日付、教える人、教わる人を選んで保存します。教える人が「教え終わった」を押すと、教わった人はレベル2になり、誰から、いつ教わったかが残ります。できるようになったら、本人がレベル3か4を申告します。部長の承認は要りません。

## 7. マニュアルの改定

- 見出し：改定したら、誰が読み直したかが分かる

1. 改定：部長が手順を書き直す。版が上がり、改訂履歴に残る
2. 知らせる：スタッフに「再確認」、部長のスキルマップに「未読」が出る
3. 読み直す：スタッフが「確認した」を押すと、2つの印が消える

- まとめの一文：改定してもレベルは変わらない。古いやり方のまま作業される心配を減らす
- 話す内容（約25秒）：部長が手順を書き直すと、版が上がって改訂履歴に残ります。以前に読んだスタッフには「再確認」、部長のスキルマップには「未読」が出ます。読み直して「確認した」を押すと、両方の印が消えます。年末調整のような改定が、全員に伝わったかを確かめられます。

## 8. 期待される効果と、既存ツールとの違い

- 期待される効果：口頭の教え直しが、マニュアルと研修の記録に置き換わる。「できる人1人」の作業に気づき、期限つきで研修を頼める。改定が全員に伝わったかを確かめられる
- 注意：実測ではなく、想定している効果です
- 既存ツールとの違い：手順の確認と、スキルレベルの確認・更新を1つにつなぐ。スタッフはマニュアルを見たその画面で、「確認した」や自己申告ができる。部長は、マニュアルと作業ごとのスタッフ状況を一緒に見られる
- 質疑で聞かれたとき（スライドには出していません）：調べた範囲では、Skills Base はスキルに手順書を添付できる（有料）が、アプリ内でマニュアルを書く機能は確認できなかった
- 話す内容（約35秒）：期待している効果は3つです。口頭の教え直しが、マニュアルと研修の記録に置き換わること。できる人が1人の作業に気づいて、期限つきで研修を頼めること。改定が全員に伝わったかを確かめられること。これは実測ではなく、想定している効果です。既存のスキル管理ツールとの違いは、手順の確認とスキルレベルの更新を1つにつなげた点です。
