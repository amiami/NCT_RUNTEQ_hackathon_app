# 要件定義

マニュあっぷは、業務マニュアルとメンバーのスキルレベルを結び付け、引き継ぎと研修の進み具合を見える化するアプリです。

画面と操作の細かいルールは [仕様書](spec.md)、画面一覧と各画面の要素は [画面設計](screens.md) にあります。

## 1. ペルソナ

### メインペルソナ：人事部長（管理者）

- 中小企業の人事部の部長。部下はスタッフ5名（ベテラン〜新人）
- 誰がどの作業をどこまでできるかを、記憶や個別の確認で把握している
- 評価・人材配置・引き継ぎ・新人教育のたびに、本人に聞いて回る手間がかかる
- 担当が変わるたび（異動のたび）に、手順を口頭で一から教え直している
- 人事の作業は本業（コア業務）ではないため後回しにされ、手順書がバラバラのままで、改訂しても伝わらない

### サブペルソナ：人事部のスタッフ

- ベテランは多くの作業を1人でこなし、後輩に教える役も担う
- 新人は、どのマニュアルを読めばよいか、誰に聞けばよいかが分からない
- マニュアルが変わっても気づかず、古いやり方のまま作業してしまうことがある

### 事例（案）

| 事例 | 今の状態 | マニュあっぷでは | ポイント |
|---|---|---|---|
| 給与計算 | できるのはベテランの山本さん1人。休むと止まるが、部長は気づいていない | スキルマップと作業ツリーに「できる人1人」と出る。研修画面から、ほかのスタッフへの研修を頼める | 属人化に気づき、教える人と期限を決める |
| 年末調整 | 10/15 にマニュアルを改定したが、誰が読み直したか分からない | 読み直していない人に「再確認」、部長のスキルマップに「未読」が出る | 改定が全員に伝わったかを確かめられる |
| 新人の研修 | 誰から何を教わったかの記録がなく、「できる」の基準も人によって違う | 「教え終わった」で研修済み（誰から・いつ）が残り、レベル3・4は本人が申告する。部長の判断が本人の申告と違うときは、管理者の見立て（▲・▼・◇）で添える | 教えた記録・本人の実感・部長の判断を分けて残す |
| 異動・引き継ぎ | 異動のたびに、手順を口頭で一から教えている | マニュアルを見て「確認した」→ 研修 → 自己申告と、どこまで進んだかが残る | 口頭での教え直しを、マニュアルと研修の記録に置き換える |

### 着想と既存ツールとの違い

- 着想：PdM が前職で使っていた力量管理表と、業務に必要な力量を整理して研修・習熟の状況を確認する考え方（ISO 9001 でも力量や教育の成果の確認が扱われている）。ただし、それだけでこのアプリの効果が実証されたわけではない
- そのほかの類似サービス：Skills Base は、スキルデータに手順書を添付できる（有料）。アプリ内でマニュアルを書く機能は確認することはできなかった。メジャーな力量の管理アプリは無料で使うことができず、UI の比較ができなかった
- マニュあっぷで大事にすること：手順の確認と、スキルレベルの確認・更新をつなぐ。スタッフはマニュアルを見たその画面で「確認した」や自己申告ができ、部長は作業ツリーでマニュアルとその作業のスタッフ状況を一緒に見られる

## 3. ユーザーストーリー（案）

> わたしは人事部長として、誰がどの作業をどこまでできるかを一目で知りたい。なぜなら、特定の人しかできない作業をなくし、休みや異動があっても業務が止まらないようにしたいからだ。

### 派生ストーリー

- 部長として、できる人が少ない作業に、誰が誰に教えるかを期限つきで頼みたい。教えるのが後回しにならないようにしたいからだ。
- 部長として、マニュアルを改定したら、誰が読み直したかを知りたい。古いやり方のまま作業されるのを防ぎたいからだ。
- 部長として、本人の申告と自分の見立てが違うときに、それを記録して研修の割り振りに使いたい。レベル3でも教えられる人に任せたり、研修が必要な人に研修を頼んだりしたいからだ。
- スタッフとして、自分がどの作業をどこまでできるかを自分で申告したい。研修を受けていなくても、覚えたことを認めてもらいたいからだ。
- スタッフとして、自分が教える予定を見逃さずに知りたい。期限までに準備して教えたいからだ。
- スタッフとして、マニュアルを見たその画面で、自分のレベルを更新したい。手順の確認と、できるようになったことの記録を、一度に済ませたいからだ。

## 4. 受入条件

### UC-1 マニュアルの確認

- 作業ツリー（分類 → 作業）から作業を選ぶと、マニュアルが表示される（アプリ内は番号付きの手順、外部サイトはリンクと「サイトを開く」）
- スタッフのツリーの各作業に、自分のレベル（0〜4）が表示される
- 「マニュアルを確認した」を押すと、レベル0の人はレベル1になる
- 一度確認したマニュアルは、改定されるまで「確認した」を押せない（薄く表示する）
- （拡張）作業名・分類で検索できる

### UC-2 マニュアルの改定

- アプリ内は「手順を書き直す（改定）」で1行＝1ステップで編集し、改定メモを入れて「改定して保存」できる
- 外部サイトは、変更内容のメモを入れて「改定あり」で保存できる
- 改定すると版が1つ上がり、改訂履歴に1件増える
- 改定してもレベルと管理者の見立ては変わらない
- 作業ごとのスタッフ状況（名前・レベル・マニュアル確認状況・研修済み）を見られる

### UC-3 改定後の読み直し・改訂履歴

- 改定前にマニュアルを確認していた人には、スタッフ画面で「再確認」、部長のスキルマップで「未読」が出る
- 改定された作業のマニュアルの上に「このマニュアルは改定されました」と出る
- 読み直して「マニュアルを確認した」を押すと、「再確認」と「未読」の両方が消える
- 改訂履歴に、日付・作業と版・種類（アプリ内／外部サイト）・変更内容が新しい順に並ぶ
- 改訂履歴の「マニュアルを見る」で、その作業のマニュアルに移る
- （拡張）スタッフの「改訂のお知らせ」で、改定の一覧と自分の状態（未確認／確認済み／未着手）が見られる

### UC-4 自己申告

- レベル1・2のとき「先輩のもとでできる」を押すとレベル3になる
- レベル1〜3のとき「最後まで1人でできる」を押すとレベル4になる（3を飛ばせる）
- 研修を受けていなくても申告できる。レベル0のときは押せない（先にマニュアルの確認が必要）
- 押せないボタンは薄く表示される
- 申告してレベルが変わっても、管理者の見立ては変わらない
- （拡張）「申告を取り消す」で申告前のレベルに戻せる。取り消せるのは直近の申告1回だけで、研修を受けた人はレベル2より下には戻らない

### UC-5 管理者の見立て

- スキルマップのマスを押すと、詳細（マニュアル確認状況、研修：済み〈○○さんから・日付〉／なし〈自分で習得〉／まだ）が出る
- 詳細で、管理者の見立てを「なし／▲（研修権限）／▼（要研修）／◇（教えるのは後回し）」から選べる。▲・▼はレベル3、◇はレベル4のときだけ選べる
- 選んだだけでは確定せず、右下の「変更を保存」を押すと確定する。研修画面と同じく、複数のマスの変更をためておき、まとめて保存できる（同じ人の複数の作業もまとめて変えられる）
- 未決定のマスは、表の中で未保存だと分かる。別のマスを押しても未決定の変更は消えない
- 未決定の変更があるまま別のタブ・スタッフ画面へ移ろうとすると「変更は保存されませんがよろしいですか？」と確認が出て、続けると未決定の変更はすべて破棄される
- 見立てはスキルマップのマスの右上と、研修画面の教える人・未研修の名前の横に表示される。▽（研修済み）の人も表示される
- スタッフ画面には、HTML の中も含めて管理者の見立てが出ない
- スタッフは見立てを付けられない

### UC-6 スキルの一覧表示

- スキルマップは行＝作業（分類ごと）、列＝スタッフで、マスにレベルの数字（高いほど濃い青）と管理者の見立てが出る
- わたしのスキル（スタッフ）に、レベル0〜4ごとの件数と、分類ごとの作業一覧（「研修済み」「再確認」バッジ・レベル）が出る
- わたしのスキルの作業を押すと、そのマニュアルに移る
- （拡張）スキルマップをスタッフ名・作業名・分類で絞り込める

### UC-7 研修を頼む

- 研修画面に、レベル0・1のスタッフか▼のスタッフがいる作業がカードで並ぶ（上段に作業名、下段に「日付｜教える人｜未研修｜研修予定」）
- 日付に初期値はない。時期が決まっている作業は、日付の横に時期の目安が出る
- 教える人は、レベル4（◇・▼以外）→ レベル3＋▲ → レベル4＋◇ の順で、最後に管理者が出る
- 未研修は、レベル0・1の人と▼の人のうち、まだ研修予定に入っていない人
- 未研修者を選んで教える人を押すと、1人につき1件の研修予定が下書きに入る（誰も選んでいなければカードの未研修者全員）
- 研修予定の追加・保存済みの研修予定の取り消し・研修予定がある作業の期限の変更をしたときだけ、右下に「変更を保存」が出る。押したときだけ「指示済みの研修」に反映される
- 研修予定がない作業の日付だけを変えても、保存の対象にならない
- 「変更を保存」が出ている状態で別の画面へ移ろうとすると確認が出て、移ると下書きは消える
- 完了前の研修予定は取り消せる

### UC-8 教え終わった記録

- わたしのスキルに「教える予定」（作業・相手・期限）と「教わる予定」（作業・教える人・期限）が出る
- 「教え終わった」を押すと、教わった人がレベル0・1ならレベル2になり（2以上ならそのまま）、研修の記録（誰から・いつ）が残る
- 教わった人のマニュアルは「確認済み」になる（改定されたら「再確認」が出る）
- ▼の人の予定では、教わった人の管理者の見立てが▽（研修済み）に変わる
- 部長の研修予定が「完了」になり、教わる予定には「研修済みになりました」と出る
- 予定の途中で教わる人が自己申告してレベル3以上になったときは、教える予定と指示済みの研修に「（本人がレベル3以上に申告済み）」と出る（▼の人の予定には出ない）
- 研修の記録は、スキルマップのマスの詳細と作業ごとのスタッフ状況で見られる
- （拡張）教える予定が届くと画面上部に通知の帯が出て、「確認しました」で消える。部長の研修予定に「教える人が確認済み」と出る

### UC-9 できる人チェック

- できる人（レベル4。◇・▼の人も数える）が1人以下の作業があると、スキルマップ上部に警告と「できる人が1人以下の作業だけ表示」ボタンが出る
- 作業ツリー・スキルマップ・研修画面に「できる人○人」が出る（1人以下のときだけ）
- 研修画面では、研修タブを開いた時点で「指示が必要」の作業が上にまとまり、その中ではできる人が少ない作業が先に並ぶ

## 5. 非機能要件（案）

| 項目 | 要件 |
|---|---|
| 応答性能 | 画面遷移は 1 秒以内 |
| 表示の制限 | スタッフ画面には、HTML やデータの中も含めて管理者の見立てを出さない |
| 認証 | ログインは作らない。画面右上の切り替えで操作する人を選ぶ（デモ用。実運用ではログインが必要） |
| 対応ブラウザ | 最新版の Chrome / Edge / Safari（PC） |
| マニュアルの保存先 | アプリ内は本文をアプリ内に保存、外部サイトは外部（OneDrive など）の文書を参照する。外部サイトの閲覧権限は参照先で管理する |
| 個人情報 | 社用パソコンからの利用を想定。MVP ではログインを作らないため、実運用には本人確認、管理者・スタッフの閲覧・変更権限、端末の制限が必要 |

## 6. 未決事項

- UC の番号と名前の確定（PdM）
- レベル0・3の名前を変えるか
- 管理者の見立ての記号の色と、マウスを乗せたときの説明の文言
- 算定基礎届・労働保険の年度更新など、時期が決まっている作業の正確な期限
- 困りごと・効果の根拠（実測はない。測定しない場合は「期待される効果」として説明する）
- 類似サービス（Skillnote・Skills Base）の現在の機能
