# 本番環境（デプロイ）

本番環境の構成と設定、デプロイの流れ、困ったときの見方をまとめます。

- 本番の URL：https://manuup.onrender.com
- Render と Neon のアカウントは、たかやまが持っています。設定を変えたいときは、チャンネルで声をかけてください

## 1. 構成

```
GitHub（main ブランチ） ──自動デプロイ──▶ Render（Web Service・Docker） ──▶ Neon（PostgreSQL）
```

| もの | 役割 |
|---|---|
| GitHub | `main` ブランチのコードが本番に出る |
| Render | リポジトリの `Dockerfile` からイメージを作り、アプリを動かす |
| Neon | 本番の PostgreSQL |

## 3. デプロイの流れ

1. Pull Request を `main` にマージする
2. Render が `main` の更新を見つけて、自動でイメージを作り直す
3. コンテナの起動時に `bin/rails db:prepare` が走り、DB の作成・マイグレーションが行われる（`bin/docker-entrypoint`）
4. Health Check（`/up`）が通ると、新しい版に切り替わる

手でデプロイする操作はいりません。

### サンプルデータ（seeds）

- 本番の DB が未初期化（テーブルがまだない）ときは、最初のデプロイの `db:prepare` がテーブルとサンプルデータ（`db/seeds.rb`）を入れる。テーブルがあれば、データが0件でも seeds は自動では入らない
- seeds は何度実行しても二重にならない作り。データを入れ直したいときは、チャンネルで相談する

## 4. うまく動かないとき

Render のダッシュボードで `manuup` を開き、次の画面を見ます。

| 画面 | 見るもの |
|---|---|
| Events | デプロイの成功・失敗の履歴。失敗したデプロイを開くと、ビルドのログが見られる |
| Logs | 起動中のアプリのログ。起動時の `db:prepare` のエラーや、画面を開いたときのエラーが出る |

| 症状 | 見るところ |
|---|---|
| デプロイが失敗する | Events で失敗したデプロイのログを開く。イメージを作るところ（`bundle install`・アセットのビルド）で止まっていないか |
| デプロイは進むが切り替わらない | Logs で起動時のエラーを見る。DB に接続できない・マイグレーションに失敗している・環境変数が足りない、など |
| 画面を開くとエラーになる | Logs でエラーの内容を見る |

## 5. 無料プランの制限

| サービス | 制限 |
|---|---|
| Render（Free） | 15分アクセスがないと止まる。止まったあとの最初のアクセスは、起動に50秒以上かかることがある。動いていられるのは、ワークスペースごとに月750時間まで |
| Neon（Free） | 容量 1GB・月 100 コンピュート時間。使わないと自動で止まる（次の接続で起動する） |

### 本番を起こし続ける（UptimeRobot）

止まったあとの最初の表示が遅くならないように、UptimeRobot（無料プラン）で本番を起こし続けています。

| 項目 | 内容 |
|---|---|
| 見に行く URL | https://manuup.onrender.com/up |
| 間隔 | 5分ごと |
| アカウント | たかやまが持っています |

- 見に行くのは `/up` だけにします。`/up` は DB に触らないので、Neon の月100時間は減りません。トップページなど、DB を読む URL にはしないでください。
- Render は manuup だけなので、ずっと起こしていても月750時間を超えません。同じワークスペースに他のサービスを足すときは、合計で750時間を超えないか確かめてください。
- 止めるときは、UptimeRobot の画面でこのモニターを止める（Pause）か、消します。ピッチ（11/7）のあとに止めてください。
- UptimeRobot を止めたあとは、デモの前に一度本番を開いて、起こしておいてください。

### デモ用データをボタンで戻す

管理者画面の共通ヘッダーには、操作する人の切り替えボタンの左に「デモ用データに戻す」を常に表示する。確認して実行すると、全業務データを削除して seeds を再投入し、操作する人を管理者に戻す。失敗時は削除も巻き戻す。環境変数の設定は不要。スタッフにはボタンを表示せず、直接リクエストを送っても受け付けない。

ログイン機能がなく、誰でもヘッダーから管理者に切り替えられるため、本番の URL を知っている人は誰でもリセットできる。スタッフ時の実行制限は、利用者本人の認証による保護ではない。デモ用データのみを扱うピッチ用途としてこのリスクを受け入れる。ピッチ中のリセットで進行が止まらないよう、本番の URL はピッチ前に広く公開せず、関係者のリセット操作は発表者と調整する。実データを扱う用途に移す際は、認証・権限の設計を見直す。
